<!-- sdlc:auto:start overview -->
Age Calculator is a generated two-part application: a Vite + React 19 single-page frontend containing the approved, reviewed screens (currently running on seeded sample data, not live API calls) and a FastAPI 0.115 backend scaffold that currently exposes only a health check endpoint because no backend architecture had been approved yet. The backend uses SQLAlchemy with a SQLite file by default (swappable via DATABASE_URL, e.g. to the PostgreSQL 16 instance defined in docker-compose.yml) and creates its tables on startup rather than via migrations.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js (for npm, Vite 6, React 19 tooling)
- Python 3.12
- pip
- Docker and Docker Compose (optional, for the PostgreSQL service in docker-compose.yml)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. Clone the repository
2. Backend: cd backend
3. pip install -r requirements.txt
4. (Optional) Start Postgres: from repo root run `docker-compose up -d` and set DATABASE_URL to point at it; otherwise the backend defaults to a local SQLite file (app.db)
5. Run the backend: uvicorn app.main:app --reload
6. In a separate terminal, Frontend: cd frontend
7. npm install
8. Run the frontend: npm run dev
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend: one router per architecture component that owns endpoints; unimplemented routes return a typed StubResponse with status 'not_implemented' so the API stays startable and documented before handlers exist
- Backend: schemas.py holds Pydantic request/response models paired to entities in models.py
- Backend: Base.metadata.create_all runs at app startup (lifespan), not at import time, so importing the app never opens a DB connection; no migrations tool is set up yet
- Backend: DATABASE_URL env var selects the database (SQLite file by default); ALLOWED_ORIGINS env var (comma-separated) configures CORS, defaulting to the Vite dev server origins
- Backend linting/formatting via ruff (ruff.toml, ruff check ., ruff format .)
- Frontend: path alias @/ maps to src/ (configured in both vite.config.ts and tsconfig.json)
- Frontend: component tests live beside the components they cover and run under Vitest with jsdom; only files under src/ matching *.test\|spec.ts(x) are collected by Vitest, leaving e2e/*.spec.ts to Playwright
- Frontend: API access is centralized in src/lib/api.ts (apiFetch helper, bearer auth via session token or shared API_SECRET_KEY) but screens currently render seeded sample data rather than calling it
- Frontend: ESLint (flat config) + Prettier enforce style; lint is run as a gate during development
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| Frontend dev server calls to the API are blocked by CORS | Ensure the backend's ALLOWED_ORIGINS env var includes the frontend's origin, or rely on the defaults (http://localhost:5173, http://127.0.0.1:5173) used when ALLOWED_ORIGINS is unset. |
| `pytest` fails with ModuleNotFoundError: app | Run pytest from the backend/ directory so pytest.ini's `pythonpath = .` setting applies. |
| `npm run build` succeeds but `tsc` reports type errors | vite build does not typecheck; run `npm run typecheck` separately to catch and fix TypeScript errors before relying on a production build. |
| Backend can't connect to a database | By default DATABASE_URL is unset and the app uses a local SQLite file (sqlite:///./app.db), requiring no server; to use PostgreSQL instead, start it with `docker-compose up -d` and set DATABASE_URL accordingly. |
| `npm run test:e2e` fails to start the backend leg of its webServer | Playwright's config expects a Python virtualenv at backend/.venv; create it and install backend/requirements.txt there (or set E2E_BASE_URL to point at an already-running deployment) before running the e2e suite. |
<!-- sdlc:auto:end troubleshooting -->
